# HANDOFF — поточний живий стан проекту (для продовження в терміналі)

Коротка «передача зміни»: що працює прямо зараз, адреси/доступи, що відкрито.
Повний довідник — `docs/INTERNAL_DOC.md`; пакет відтворення — `delivery/`.

Станом на: **2026-10-15**. Гілка: `claude/luckfox-pico-linux-setup-wrz9u6`.

## Тракт
`Seek 640 → RV1106 (RGA-апскейл 1280×1024 → H.265 → RTSP) → Beam TX → радіо → Beam RX → RK3588 → HDMI`

## Доступи й адреси (живі)
| Пристрій | Доступ | Стан |
|---|---|---|
| **RV1106 (борт)** | `ssh root@192.168.1.10` (пароль `luckfox`) | ✅ РТSP живий: `rtsp://192.168.1.10:554/stream=0`, режим rtsp, камера піднята, апскейл 1280×1024 |
| **Beam TX (mini)** | у полі Cam IP: `192.168.1.10`, URL `rtsp://192.168.1.10:554/stream=0` | тягне камеру |
| **Beam RX (земля)** | `192.168.1.21` | пушить RTP → `192.168.1.2:5700` |
| **RK3588 / BPI-M7** | `ssh armsom@192.168.0.162` (WiFi) | ⚠ пароль не підходить, host key змінився → схоже, ПЕРЕПРОШИЛИ; треба скинути пароль / перевірити |
| Ноут | `kornev@fedora` | enp98s0 у підмережі плати; wlan1 — керування |

> RV1106 eth0 MAC: `ee:28:0c:f8:40:4c`. На eth0 поряд з 192.168.1.10 буває зайва 10.42.0.125 (можна прибрати).

## Що працює / перевірено
- Бортовий бік **повністю**: камера → RGA-апскейл 1280×1024 → H.265 → RTSP (ffplay з ноута показує тепловізор).
- Повний тракт через Beam на RK3588 — відео виводиться (робочий приймач: **ffmpeg RTP/RTCP + keepalive-пінг + софт-декод → gst → HDMI**).

## Ключові факти Beam (щоб не передобати)
1. Beam заводиться **лише** приймачем, що шле **RTCP** (ffmpeg/ffplay), не голим `gst udpsrc`.
2. Потрібен **безперервний keepalive-пінг** на `192.168.1.21` (інакше Beam глушить потік).
3. Потік на землі: **RTP/UDP H.265, payload 96, `192.168.1.2:5700`**; адреса приймача — лише на порту з кабелем.
4. Втрати радіо → апаратний `mppvideodec` чорніє; софт-декод (ffmpeg) терпить. Синк для софт-кадрів: `xvimagesink`/`glimagesink` (НЕ `rkximagesink`).
