# UPSCALE — апскейл тепловізійного кадру (640×512 → 1280×1024)

Тепловізор Seek дає **640×512**. Для трансляції/дисплея кадр масштабуємо до
**1280×1024**. Це робиться **на борту (RV1106) апаратно через RGA** — усередині
того самого конвеєра, що кодує H.265. Окремої програми в польовому тракті не
треба: апскейл вбудований у sender.

## Вміст папки
| Файл | Що це |
|---|---|
| `upscale-frame.sh` | ДОПОМІЖНИЙ софтовий апскейл ОДНОГО кадру (ffmpeg) — для тестів/скріншотів |

---

## 1. Робочий апскейл — апаратний, RGA (у sender'і RV1106)

Живе в коді бортового sender'а (`../RV1106/src/rtsp_sender.cpp`, клас `Pipeline`).
Один виклик RGA робить **і конвертацію формату, і масштаб** за один прохід:

```
вхід:  YUYV 4:2:2, 640×512     (кадр з камери, V4L2)
        │  RGA im2d: imresize(input_image_, output_image_)
        ▼
вихід: NV12, 1280×1024         → далі у VEPU (H.265)
```

Ключове в коді:
- вхід описаний як `RK_FORMAT_YUYV_422`, 640×512;
- вихід — `wrapbuffer_handle(... 1280×1024 ...)` у форматі NV12;
- сам апскейл+конверсія — `IM_STATUS = imresize(input_image_, output_image_)`;
- розмір виходу задають прапорці `--output-width/--output-height` (деф. 1280×1024).

**Чому RGA, а не софт:** RGA — апаратний блок 2D; масштаб 640×512→1280×1024 ~4.6 мс,
майже без CPU. Софт (ffmpeg/OpenCV) на RV1106 з'їв би CPU і впав по fps.
Обмеження RGA: масштаб 0.0625..16×; вхід YUYV422; вихід RGBA/RGB888/RGB565/NV12.

**Як змінити роздільність виходу:** прапорцями sender'а, напр. `--output-width 1280
--output-height 1024` (або менше — під смугу Beam). Перекомпіляція не потрібна.

## 2. Допоміжний софтовий апскейл — `upscale-frame.sh`

ТИМЧАСОВИЙ інструмент для **одного кадру** (скріншот/діагностика), НЕ для потоку.
Потребує `ffmpeg` на платі.

```sh
sh upscale-frame.sh <in.yuyv|in.png> [OUT_PNG] [SIZE]
# приклад: захопити кадр і масштабувати до 720:
#   ssh root@192.168.50.2 'cat /dev/video0 | head -c 655360 > /root/frame.yuyv'   # 640*512*2
#   sh upscale-frame.sh /root/frame.yuyv /root/up_720.png 720
```
Вхід: сирий `YUYV 640×512` або готовий PNG/JPG. Робить `normalize` (контраст
тепловізора) + вписує 5:4 у квадрат `SIZE×SIZE` з letterbox. Виходить PNG.

> Це саме допоміжний шлях (жере CPU). У продакшн-тракті апскейл робить RGA
> у sender'і (розділ 1).
